This runs entirely in your browser — no build step, no backend, independent of any existing tournament-tracker code. It stands in for two of the riskiest pieces from the Milestone 1 architecture proposal: real capability detection (what does this device actually report for its cameras, and can two streams really run at once?) and an undo-able, event-sourced point ledger, rather than a single overwritten score. It cannot exercise AVCaptureMultiCamSession itself or true hardware-synchronized dual recording — browsers don't expose that — so a "yes" here is a good sign, but the native iOS path (Milestone 4 onward) is still the one that matters for production. Scoring uses simplified rules (no tiebreak game) for this proof of concept.
